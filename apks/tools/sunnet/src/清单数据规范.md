# 清单方案包 · 数据规范（sunnet.pack v1）

> 这份文件是给**别的 AI**（ChatGPT / Claude / 豆包 / DeepSeek…）看的：
> 你把「[给 AI 的提示词](#6-给-ai-的提示词直接复制这段)」整段发给它，
> 它按规范吐一份 JSON 回来，你在 App 里粘贴导入 —— **整页采购清单 / 接线表 / 组装步骤就换成新产品了**。
>
> App：`com.hua.sunnet`（太阳网控制器）。规范版本 v1，App 版本 1.0。

---

## 0. 三步流程图

```
   ① 复制提示词            ② AI 吐 JSON              ③ App 导入
┌──────────────┐      ┌──────────────────┐      ┌────────────────────┐
│ App：散装页   │      │ {                │      │ 散装页 → 导入方案    │
│ 复制格式说明  │ ───▶ │  "format": ...   │ ───▶ │ → 从剪贴板粘贴 → 导入 │
│ （或本文档）  │      │ }                │      │ 整页换成新产品清单    │
└──────────────┘      └──────────────────┘      └────────────────────┘
                                                         │
                          想改回去：散装页 →「恢复内置」 ◀──┘
```

- **导入** = 覆盖式：导入成功后散装页整页换成新数据；勾选进度按方案 `id` 分开存，互相不干扰。
- **导出**：散装页 →「导出方案」把当前数据复制成同一格式，可以再交给 AI 改。
- 一次只存一份方案包；想同时留好几个产品，就各自存成 `.json` 文件，用时导入。

## 1. 顶层结构

```jsonc
{
  "format": "sunnet.pack",     // 必填，固定字符串
  "ver": 1,                    // 必填，固定 1
  "meta":   { ... },           // 必填：这份方案的标题、产品、备注
  "groups": [ ... ],           // 必填：1 个起，每个是一套方案（方案 A/B/C/D…）
  "volt":   { ... },           // 选填：电压分层表
  "power":  "…",               // 选填：纯文本走线图（等宽字体显示，用空格对齐）
  "wiring": [ ... ],           // 选填：接线表
  "steps":  [ ... ],           // 选填：组装步骤（有顺序）
  "notes":  [ ... ],           // 选填：硬注意（会烧东西的那种）
  "pinPatch": "…",             // 选填：固件引脚表 / 需要改的代码
  "compare": { ... },          // 选填：两方案对比表（3 列）
  "extraCards": [ ... ]        // 选填：自定义补充卡片
}
```

> 除 `format` / `ver` / `meta.title` / `groups` 外都可以省。省掉的卡片在 App 里不显示，不会报错。

## 2. 字段表

### 2.1 `meta` — 方案身份

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `title` | ✅ | string | 大标题，例：`"阳台自动浇花系统 · 散装方案"` |
| `id` | 建议 | string | 英文小写标识（勾选进度按它分开存）。例：`"watering"`。**同一 App 里换产品一定要换 id**，否则勾选进度会串 |
| `product` | 建议 | string | 一句话说做什么 |
| `subtitle` | | string | 副标题 |
| `currency` | | string | 默认 `"CNY"` |
| `updated` | | string | 日期 `"2026-10-17"` |
| `note` | | string | 价格口径说明，例：`"价格是淘宝中位价，下单前自己比价"` |

### 2.2 `groups[]` — 方案分组

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | | string | 组标识，例 `"A"` |
| `title` | ✅ | string | 卡片标题，例 `"方案 A · 基础散装版"` |
| `sub` | | string | 标题右边小字，例 `"约 ¥220"` |
| `kind` | | `"check"` \| `"plain"` | `check` = 可勾选的采购清单（**只能有一个**，通常第一组）；`plain` = 只读参考清单（其余全是） |
| `intro` | | string | 卡片开头说明 |
| `foot` | | string | 卡片底部补充 |
| `skip` | | string[] | 「只买最小集」要跳过的 `item.id` 列表 |
| `items` | ✅ | object[] | 至少 1 项，见下 |

### 2.3 `items[]` — 一个零件 / 一个模块

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `name` | ✅ | string | 名字（带关键型号最好），例 `"DRV8871 直流电机驱动模块（3.6A）"` |
| `id` | 建议 | string | 组内唯一；不写会自动补 `g0-1` 这种 |
| `qty` | | number | 数量，默认 1 |
| `price` | | number \| string | **数字 = 单价**（App 会 `price × qty` 求合计）；**字符串 = 原样显示**（例 `"¥38-55"`，不参与合计） |
| `kw` | 强烈建议 | string | 搜索关键词，**有它才有「淘宝 / 拼多多 / 1688」按钮**。例 `"DRV8871 电机驱动模块"` |
| `volt` | 强烈建议 | string | 电压/电源要求，例 `"5V 供电 / 触点侧 12V"`；无源就写 `"无源"` |
| `spec` | 强烈建议 | string | 买之前必须核对的具体规格（口径、电流、阻值、接口…） |
| `part` | | string | 对应自制 PCB 的位号（`U6` / `J4`），没有就留空 |
| `why` | | string | 它在系统里干什么 |
| `links` | | object | 覆盖默认搜索链接：`{"taobao":"…","pdd":"…","1688":"…"}` |

**数组简写**（省 token 用，等价）：`["名称", "搜索词", 数量, 单价, "规格", "电压", "位号", "干嘛用"]`

### 2.4 `volt` — 电压分层

```json
"volt": {
  "note": "整片说明（可省）",
  "rows": [ { "v": "12V", "who": "给谁用", "how": "从哪来", "warn": "踩了会怎样" } ]
}
```
也可数组简写：`["12V","给谁用","从哪来","警告"]`。

### 2.5 `wiring[]` — 接线表

```json
{ "part": "J4 土壤", "mod": "电容式土壤模块 AO", "gpio": "GPIO1", "volt": "0~3.0V 模拟", "note": "必须 ADC1" }
```
数组简写：`["J4 土壤","电容式土壤模块 AO","GPIO1","0~3.0V","必须 ADC1"]`。
`gpio` 留空时，这一行会显示成一行说明文字（不显示 GPIO 徽标）。

### 2.6 `steps[]` — 组装步骤

```json
{ "t": "先只搭电源，别接主控", "d": "12V → 保险 → 降压，用万用表把输出调到 <b>5.0V</b>" }
```
数组简写：`["标题","说明"]`；只给字符串也行（当标题）。
**要求：一步只做一件事，能验证（量电压 / 听声音 / 看灯）。**

### 2.7 `notes[]` — 硬注意

```json
{ "level": "warn", "text": "<b>缺水保护必须有。</b>泵空转十分钟就烧" }
```
`level`：`"warn"`（黄底，默认）或 `"info"`（蓝底）。只写字符串也行。
**要求：写「为什么」，不写空话（不要“注意安全”这种）。**

### 2.8 `pinPatch` — 固件改动

一段纯文本（等宽显示）：要改的常量、要替换的文件、要跑的编译命令。

### 2.9 `compare` — 对比表（固定 3 列）

```json
{
  "head": ["项目", "自制 PCB", "散装模块"],
  "rows": [ { "k": "一次投入", "a": "¥450~800", "b": "¥220", "good": "b" } ]
}
```
`good` = 哪一列高亮成绿色（`"a"` 或 `"b"`，默认 `"b"`）。

### 2.10 `extraCards[]` — 自定义卡片

```json
[ { "title": "怎么让它自己决定浇不浇", "html": "阈值低于它就开始浇<br />• …" } ]
```

## 3. 给 AI 的硬规则（写进提示词里，越具体越少出错）

1. **只输出 JSON**：不要解释、不要前言后语、不要 `//` 注释、不要尾逗号 `,}`。
   （App 能容忍 ```json 围栏和尾逗号，但干净输出最保险。）
2. **中文**写内容，价格用人民币、取**中位价**（别写 ¥1 也别写 ¥9999）。
3. 文本里只允许这几个行内标签：`<b> <i> <code> <br>`，其它 HTML 会被转义成文字。
4. `id` 在同一组内唯一、用英文/数字；`kw` 写**买家会在淘宝搜的词**（不要写型号内部编号）。
5. 每个零件的 `price` 要**能给数字就给数字**（好算合计）；价格波动大的写字符串区间。
6. 「危险/易错」的地方必须进 `notes`；「顺序不能乱」的必须进 `steps`。
7. **电气常识要守住**：3.3V 逻辑别接 5V 模拟输出；强电（220V）单独走并加漏保；缺水/超时要有限位式保护。
8. 不确定的参数（口径、扬程、电流）**要么不写，要么写「按你的实测选」**，不要编。

## 6. 给 AI 的提示词（直接复制这段）

```text
请给我做一份「采购 + 组装 + 接线」清单，按下面这个 JSON 规范输出（sunnet.pack v1），
我要把这份 JSON 导入一个安卓 App 的「散装」页，所以格式必须严格对。

== 输出格式（只输出 JSON，不要解释、不要 markdown 围栏之外的字、不要注释、不要尾逗号）==

{
  "format": "sunnet.pack",
  "ver": 1,
  "meta": { "id": "<英文小写标识>", "title": "<产品 · 方案名>", "product": "<一句话>",
            "subtitle": "<可选>", "currency": "CNY", "updated": "<YYYY-MM-DD>",
            "note": "价格为参考中位价，下单前请自行比价" },
  "groups": [
    { "id": "A", "title": "散装采购清单", "sub": "约 ¥???", "kind": "check",
      "intro": "点一行 = 勾上已买", "skip": ["<可省的第二阶段零件 id>"],
      "items": [
        { "id": "<组内唯一英文 id>", "name": "<零件名 + 关键型号>", "qty": 1, "price": 45,
          "kw": "<淘宝搜索词>", "volt": "<电压/电源要求，无源写「无源」>",
          "spec": "<买前必须核对的具体规格：口径/电流/阻值/接口>",
          "part": "<对应自制板位号，可空>", "why": "<它在系统里干嘛>" }
      ] },
    { "id": "B", "title": "方案 B · <升级方向>", "sub": "约 ¥???", "kind": "plain",
      "intro": "<什么时候该用它>", "items": [ "<同样的 item 结构>" ] },
    { "id": "C", "title": "方案 C · <另一种供电/执行器>", "kind": "plain", "items": [ "…" ],
      "foot": "<换这套要改什么>" },
    { "id": "D", "title": "方案 D · 买成品", "kind": "plain", "items": [ "…" ] }
  ],
  "volt": { "note": "<整片说明>",
            "rows": [ { "v": "12V", "who": "<给谁用>", "how": "<从哪来>", "warn": "<踩了会怎样>" } ] },
  "power": "<纯文本走线图，等宽字体，用空格 / ─ 对齐，把电源分级写清楚>",
  "wiring": [ { "part": "<位号>", "mod": "<接哪个模块的哪个脚>", "gpio": "<GPIO 号>",
                "volt": "<电压/信号类型>", "note": "<要点>" } ],
  "steps": [ { "t": "<第一步做什么>", "d": "<具体怎么做、怎么验证>" } ],
  "notes": [ { "level": "warn", "text": "<b>会烧东西/会误动作的坑</b>，写清为什么" } ],
  "pinPatch": "<如果要改固件，把要改的常量/文件/命令写在这里，纯文本>",
  "compare": { "head": ["项目", "自制 PCB", "散装模块"],
               "rows": [ { "k": "一次投入", "a": "¥???", "b": "¥???", "good": "b" } ] },
  "extraCards": [ { "title": "<补充说明>", "html": "<b>可以</b>用 <br /> 换行>" } ]
}

== 规则 ==
1. 文本里只允许 <b> <i> <code> <br> 这几个行内标签，其它 HTML 别写。
2. 每个零件的 price 能给数字就给数字（App 用 price×qty 算合计）；价格波动大的写成字符串区间如 "¥38-55"。
3. 每个零件都要有 kw（买家真会搜的词）、volt、spec；spec 要具体到能防止买错。
4. id 在同一组内唯一，用英文小写和短横线。
5. 电气常识必须守住：3.3V 逻辑不要用 5V 器件去灌模拟输出；220V 强电单独走并加漏保；
   失水/超时/限位这类保护要写成 notes 里的硬注意。
6. 不确定的参数（口径、扬程、电流等）不要编，写「按实测选」或干脆不写。
7. 方案 A=最便宜能跑通的散装版；B=升级/长期运行版；C=换了供电或执行器的版本；D=买成品（0 开发）。
   每一组都要有 items；方案 A 的 kind 必须是 "check"，其余是 "plain"。
8. 步骤要可验证（能量电压、能听声音、能看灯），一步只做一件事。
9. 只输出 JSON 本身。

== 我要做的产品 ==
产品名/用途：
供电情况：（例如：阳台有 220V 插座 / 只有 12V 电池 / 电池 + 太阳能）
执行器：（电机？水泵？电磁阀？几路？功率？交流还是直流）
要接的传感器：（土壤湿度、光照、雨、风、限位、水位…）
控制方式：（要手机 App 蓝牙连？要自动+手动？要几个按键？）
预算：（例如 200 元以内，能用就行）
安装环境：（室内 / 阳台 / 户外日晒雨淋）
```

**只想让它改现有方案**时，把 App 的「导出方案」结果整段粘给它，然后说：
`按同样的格式，把 XXX 部分改成 YYY，并保持其它字段不变，只输出 JSON。`

## 7. 导入到 App

1. 手机上打开 **太阳网控制器** App → 底部 **散装** 页；
2. 点 **导入方案**；
3. 二选一：
   - **从剪贴板粘贴**：把 AI 给的 JSON 复制了再点（注意别漏了开头的 `{`）；
   - **选文件…**：AI 把 JSON 存成文件发你 → 存到手机 → 选它；
4. 点 **导入**。

导入成功会提示「✔ 导入成功：标题 · N 个方案 · M 个条目」，页面立刻刷新。
失败会显示中文原因（第 8 节对照表），原方案不会被动坏。

> 用电脑操作时：`adb push 方案.json /sdcard/Download/`，再在手机文件选择器里找 Download。

## 8. 报错对照表

| 提示 | 原因 | 怎么改 |
|---|---|---|
| `没找到 JSON 对象（要以 { 开头、} 结尾）` | 复制时漏了花括号，或 AI 没给 JSON | 让 AI 重新只输出 JSON |
| `JSON 语法错误：…` | 引号/逗号/括号不配对，常见是尾逗号 `,}` | 让 AI 重新输出；App 会自动修尾逗号、中文引号 |
| `format 必须是 "sunnet.pack"` | AI 自己起了格式名 | 让 AI 改回 `"sunnet.pack"` |
| `ver=… 比本 App 支持的 v1 新` | 版本号写大了 | 让 AI 写成 `1` |
| `缺少 groups` | 顶层没有 `groups` 数组 | 让 AI 补 |
| `groups[0].items 为空` | 某个方案没零件 | 让 AI 补内容 |
| `groups[0].items[0] 缺少 name` | 零件没名字 | 让 AI 给 `name` |
| `volt.rows[0] 不是对象` | 该写对象的地方写了数字/字符串 | 让 AI 按规范改 |
