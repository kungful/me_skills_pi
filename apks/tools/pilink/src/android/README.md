# Pi 通知（pilink）—— 自研订阅端

这是 `pi-android-link` 的手机端：**推送全链路自研，不依赖任何第三方推送服务**（2026-09-24 起）。

- **消息中转** 就在派发台里：`console-server.mjs` 的 `/pi/*` 一组端点
- **判定层**（`lib/classify.mjs`）、**看门狗**（`watchdog.mjs` 的判定流程）完全复用，只把出口换成 `lib/broker.mjs`
- 手机端是一个自己的 APK：不需要厂商推送账号、不需要 FCM、不需要 HTTPS

---


## 为什么非换不可（不是"感觉不稳"，是源码级缺陷）

对照对象是上一版第三方客户端（已弃用，不再随仓库分发）：
`aapt2 dump badging` 读出来的 targetSdk = 36）：

| # | 旧客户端的做法 | 源码位置 | 后果 |
|---|---|---|---|
| 1 | `readTimeout(0)` + `pingInterval(3min)` | `util/HttpUtil.kt:65-69` | 链路**静默**死亡时，要 3 分钟才发 ping、再等一个周期没 pong 才认错 → **最长 ~6 分钟**才知道自己掉线 |
| 2 | 重连靠 `AlarmManager.setExact`，未授予 `SCHEDULE_EXACT_ALARM` 时**只打一行日志就放弃** | `service/WsConnection.kt:114-123` | Android 14+ 对该权限默认拒绝、ColorOS 上还找不到授权入口 → **连接永远不会自己重连**，只能等无关事件把它拉起来（WorkManager 周期任务最小 15 分钟）→ 就是观测到的 **20 分钟盲区** |
| 3 | 只有 WebSocket 一条路 | `service/SubscriberService.kt` | WS 挂了就全瞎，没有任何兜底 |

实测证据（2026-09-24）：当时那台中转服务端 `Server stats` 705 个采样点覆盖 706 分钟**连续无中断**，
只有 `subscribers` 在 `1 → 0 → 1` 抖动 → **服务端一直活着，是手机端自己掉的**；
离线段：`20 分钟`(×1)、`5 分钟`、`4 分钟`、`1 分钟`。

## 本客户端的对应设计

| 维度 | 旧客户端 v1.25.2 | pilink |
|---|---|---|
| 死连接检测 | ping 3 分钟 → 最长 ~6 分钟 | ping **20s**（≤40s 暴露）+ 独立「静默看门狗」（90s 无任何帧即重连，不依赖单个库的行为） |
| 重连调度 | `setExact` + 特殊权限，缺权限则静默放弃 | **常驻协程 while 循环**，退避 `1/2/3/5/8/13/21/30s`，**不需要任何权限**；外加 `setAndAllowWhileIdle` 5 分钟自愈闹钟（非精确、免权限） |
| 兜底通道 | 无 | **HTTP 轮询**：`GET /<topic>/json?poll=1&since=<id>`，WS 正常时 30s 一次、异常时 5s 一次 → 即使 WS 彻底退休，送达仍 ≤1 个轮询周期 |
| 断线补收 | 有（`since=`） | 有（同样带 `since=<lastId>`，且 WS/轮询两条路按消息 id 去重） |
| 前台服务类型 | `specialUse` | `specialUse`（**不用 `dataSync`** —— Android 15+ 对它有每 24 小时 6 小时超时） |
| 唤醒 | `PARTIAL_WAKE_LOCK` | 同 + 自愈闹钟闭环 |
| 钉住那个坑的断言 | — | `verify-apk.mjs` 里有硬断言：**清单里不许出现 `SCHEDULE_EXACT_ALARM`** |

## 异地通知：出门在外也能收（2026-09-26 加）

App 不再只连一个地址，而是手里有一份**候选出口清单**，谁通用谁：

| 来源 | 什么时候更新 |
|---|---|
| 手动填的「派发台地址」 | 设置页保存时 |
| `/app` 页「一键配置」深链里的 `bases=` | 出门前在家点一下就预置好 |
| 推送流 `open` 帧、每 10 个心跳、每条消息里的 `bases` | 自动（所以隧道换域名、公网 IP 变了都能学到） |

切换规则（`EndpointManager.kt`）：

- 手动地址永远排第一；当前在用的地址先试
- 连不上就换下一个，**重连循环本身就是探测**（不额外发请求，不耗电）
- 连续失败 2 次排到最后，连通一次清零
- HTTP 401/403 时**不换**地址 —— 令牌是同一个，换也没用
- `autoSwitch=false` 时死用手动地址（排查问题时有用）

设置页 →「异地通知」里有：自动切换开关、候选清单（哪个在用 / 哪个连不上×N）、
`挨个探测`（当场挨个 ping 一遍）、`添加并启用`（手填一个反向代理地址）。
主界面第二行会显示当前出口，连在异地地址上时标「异地」。

对应的服务端内容见 [../ARCHITECTURE.md](../ARCHITECTURE.md) 第 5b 节。

## 可调参数（都在手机上改，服务端不用管）

设置页 → 「心跳与重连」，改完点「保存并生效」立刻重建订阅端（`PiLinkService.ACTION_RELOAD`）：

| 设置项 | 范围 | 默认 | 含义 |
|---|---|---|---|
| 心跳间隔 | 5–300s | **20** | 多久没收到任何帧就发一个 WebSocket PING；再等同样久没 PONG 就判死 → 死连接最迟 2×心跳暴露 |
| 静默判死 | 30–900s | **90** | WS 帧 + HTTP 轮询**两条路都**静默这么久 → 强制重连 |
| 轮询兜底·已连接 | 10–600s | **30** | 独立第二条通道，补 WS 漏掉的 |
| 轮询兜底·未连接 | 5–300s | **10** | 断线时的重试频率 |

- 「静默判死」会被自动保持在 **≥ 心跳×2**（否则看门狗和心跳会互相打架）；超出范围的值自动夹到边界并回填到输入框，不会出现「以为改了其实没改」。
- 设置页底部「当前状态」里有一行 **生效节奏**，用来确认改动真的生效了。
- 更短 = 更早发现、恢复更快，代价是无线电唤醒更频繁、耗电略增。
- **注意边界**：这些参数只在进程能跑的时候起作用。Doze 期间进程被冻结、系统给应用断网，参数再激进也没用 —— 那个场景只能靠**电池白名单**（或缺席时的系统级推送通道）。
- **keepalive 现在由 App 决定**：App 把「心跳间隔」当 `ka` 传给服务端（`/pi/stream?ka=`），服务端按它发 keepalive；App 侧的 OkHttp 读截止取 `2×ka+5` 秒。所以「多久发现断线」完全在手机上可调，PC 侧没有任何需要调的东西。

## 关于诊断代码

为定位"推送到不了手机"曾经加过一层诊断上报（`/pi/diag` + `diag.jsonl` + 每 30 秒的 alive 心跳）。
**问题定位完成后已全部移除** —— App、派发台（路由与落盘）、以及相关断言都不再包含任何诊断代码。

保留下来的是**功能**而不是诊断：
- **送达回执**（`/pi/ack` → `acks.jsonl`）：这是"到底送达没有"的正常能力，不是诊断
- **首屏通知告警条**：系统把通知关掉时明确告诉你（`Notifier.blockedReason`）
- **看门狗启动时的出口自检**（一行日志）：防止"改了中转地址却没重启常驻进程"再发生

## 构建与验收

```bash
cd C:\pi-link\android

# 构建（本机 gradle 8.7 + JDK 21 + SDK 33/34）
set ANDROID_HOME=<ANDROID_SDK>
<GRADLE_HOME>\bin\gradle.bat assembleDebug --no-daemon

# 验收：35 项确定性断言（APK 清单 17 项 + 自研中转协议契约 12 项 + 其余 6 项）
node verify-apk.mjs
```

`verify-apk.mjs` 的 B 组是**客户端与真实服务端的协议契约**，其中一条
（现在是 `B4 返回的是 NDJSON`）是实测踩出来的：长连接是**一行一个对象的 NDJSON**，
不是 JSON 数组 —— 用 `JSONArray` 解析会让轮询兜底静默失效。这条现在是断言。

## 装机（手机侧）

```
手机浏览器打开  http://192.168.1.100:8787/app
  ① 点「下载 APK」        —— 短地址 /apk，永远给目录里最新那个（不用记版本号）
  ② 点「一键配置并启动」   —— 深链 pilink://setup?base=&token=&ack=，自动填好三栏
  ③ 弹「电池白名单」就点「去设置」并允许
```

装完在设置页最底部确认版本号，主界面状态应是「已连接」。

**ColorOS（OPPO）必做三项**，否则照样被系统掐：

| 设置 | 路径 |
|---|---|
| 允许后台活动 | 设置 → 应用管理 → Pi 通知 → 耗电管理 → 允许后台活动 / 允许后台运行 |
| 自启动 | 设置 → 应用管理 → Pi 通知 → 自启动 → 允许 |
| 锁后台 | 最近任务里把这个卡片**下拉加锁**（防手滑清理） |

**电池白名单是硬要求**：Android 息屏闲置后进 Doze，会给所有应用断网，只有白名单里的豁免。
不需要「闹钟和提醒」权限 —— 重连是常驻协程 + 非精确闹钟自愈。

## 协议（自研）

| 端点 | 作用 |
|---|---|
| `POST /pi/publish` | 发一条通知（要令牌）；分配 id/seq/time，写环形缓存并扇出 |
| `GET /pi/stream?since=&ka=` | NDJSON 长连接：先补发 since 之后、再实时推、每 `ka` 秒一条 keepalive |
| `GET /pi/messages?since=` | 只拿缓存；游标支持 `none` / `all` / `<id>` / `10m` 时间窗 |
| `POST /pi/ack` | 送达回执（免令牌，只追加一行 `acks.jsonl`）|

游标语义：`since=none` 不补旧消息（首装别一次弹一堆）；游标不在缓存里（被轮转掉）时**全给**，宁可重复不可丢。
