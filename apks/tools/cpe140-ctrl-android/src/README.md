# CPE140 控制台（安卓版）

易阔 **CPE140** / BHU BXO2000n-2S-Lite 中继器的手机控制台。
**免登录**，因为走的是设备自己的两个未认证通道（Web API + `timectrl` 命令注入）。

```
package   com.picpe.cpe140
version   1.4.0
minSdk    24 (Android 7.0)      targetSdk 37
签名      cpe140.jks (alias cpe140 / cpe140123)   ← 自签名
```

## 编译

```bash
# 需要 JDK 17+（本机用 JDK 24）与 Android SDK（compileSdk 37）
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

> 本项目放在含中文的路径下，`gradle.properties` 里加了 `android.overridePathCheck=true`。
> 如果 aapt2 在中文路径下抽风，把工程挪到纯英文路径再编。

### 断网诊断 / 分级软修复（断网先跑这个）

中继器“突然没网”分很多种，很多时候**重启根本没必要**。维护页顶部两个按钮：

* **一键诊断**：只读取证，不改设备任何东西。逐层看上行无线信号 → 默认网关/ARP →
  三层连通性（网关/外网/DNS）→ **固件的「强制门户」劫持链** → 上行接口 wan →
  相关守护进程 → 系统日志，最后给出**判定**：假断网 / 上行无线不通 / 上游宽带问题 /
  DNS 坏了 / 一切正常。
* **立即救网**：按六级阶梯 `/etc/netfix.sh` 从最轻的动作开始，网络一通就停：
  强制重新检测 → 放开被固件禁用的上行 → 重拨 DHCP → 重新关联 → 重起接口 → wifi reload。
  全程最多约 1 分半，比重启温和得多。不放心先点「干跑」。

> 最典型的假断网：**打开管理页就又能上网**。其实外网一直通，只是固件自带的
> `detect_internet` 把 DNS(53)/HTTP(80) 劫持到自己页面上。软修第一步 `kill -USR1` 就清掉。

### 断网看门狗（自动重启）

设备上跑 `/etc/netguard.sh`（每 2 分钟由 cron 巡检一次）：

* 探测 `223.5.5.5` / `114.114.114.114`，任一通 → 计数清零；
* 连续 `N/2` 次全不通（默认 10 分钟）→ 先跑一遍 `/etc/netfix.sh` 分级软修复，
  还是不通才 `sync; sleep 3; reboot`（救得回来就不重启）；
* **30 分钟冷却**：两次自重启至少隔 30 分钟；
* **单次断网最多重启 3 次**：到量后改为每 6 小时才试一次，**不会无限重启**；
  网络一恢复就重新计时、重新给满 3 次；
* **和「定时重启」互不干扰**：脚本名与命令行都不含 `reboot` 子串，
  不会被 `/etc/init.d/autoreboot` 的 `sed -i '/reboot/d'` 误删；
* 计数与日志放 `/tmp`（内存盘，零 flash 磨损，重启自然归零）。

App 里点「**干跑测试**」只算一遍并告诉你「现在断网的话会做什么」，**绝不重启**。
（「诊断/救网」里的「干跑」则只打印软修会执行哪几步，同样绝不动设备。）
默认装机时脚本已放好但 **cron 未启用**，由你点「开启看门狗」才真正生效。

首次打开会自动连 `192.168.188.254`（可改）。**手机要能路由到设备**：
连设备自己的 WiFi，或连它后级的网络。

## 实现要点

* **HTTP 免代理**：直接 `HttpURLConnection`，不走系统代理。
* **回显通道**：`cmd > /tmp/.cpeout` + `/www/.cpeout` 符号链接 → `GET /.cpeout`。
  载荷自身不输出字符，写回的 uci 值与原值相同 —— 不污染定时重启规则，无需还原。
* **权限补刀**：`cp` 会带来源文件权限（如 `/etc/shadow` 的 600），uhttpd 对 600 回 403，
  所以注入载荷末尾统一 `chmod 644`。
* **载荷字符限制**：不能出现 `` ` `` `"` `\` `$` `{` `}`（前四个会把双引号值括断
  或被外层 shell 抢先展开，大括号会被 CGI 拒掉）。含这些字符的命令自动改走"上传脚本 + `sh` 执行"。
  单次内联载荷 ≤ 620 字节，注入总长 ≤ 880（设备上限约 960）。
* 文件读写走 SAF（`CreateDocument` / `OpenDocument`），**不需要存储权限**。
* 边到边（targetSdk 35+ 强制）已在 `MainActivity` 里手动补系统栏内边距。

## 回显通道：搜「Not Found」那个报错是什么（v1.4.0 修）

工具不在设备上常驻，它靠一条「土电话线」把命令输出取回来：命令输出重定向到
`/tmp/.cpeout`，再把它链接成 `/www/.cpeout`（`/www` 是 uhttpd 的根目录），
最后 `GET /.cpeout` 读回来。这套链路叫**回显通道**。

问题在于：`/tmp` 是内存盘，**设备一重启就被清空**；而 `/www/.cpeout` 是写在
flash（overlay）上的符号链接，**重启后还在** —— 于是它变成一个断链，
`GET /.cpeout` 不再是什么“输出”，而是 uhttpd 的一张 **404 网页**：

```
<h1>Not Found</h1>The requested URL /.cpeout was not found on this server.
```

v1.3.0 以前这里不管三七二十一，把 HTML 当“命令输出”显示出来，所以就出现了
「干跑一下，结果给我一段网页」这种看不懂的东西；而且通道坏了也不会自己好，
只能重启 App。v1.4.0 做了两件事：

* **认得出来**：非 200 / body 以 `<h1>` 开头 → 判定为通道丢了，不再当输出显示；
* **自己重铺**：作废缓存标志 → 重建 `/tmp/.cpeout` + `/www/.cpeout`（**不截断**
  刚写好的输出）→ 先重读，真不行才重跑一次命令。

手动保险：维护页新增「**重铺连接通道**」（重建并回读 `ls -l /www/.cpeout` + `id` 验证）
与「**看请求日志**」（列出最近 6 条 HTTP：状态码 / 路径 / 字节数，排查时一眼定位）。
PC 端 `cpe140.py` 同样修了（只是它每次重跑进程都会重铺，不容易撞上）。

> 同理，设备上执行 `: > /tmp/.cpeout; ln -sf /tmp/.cpeout /www/.cpeout` 也能手工修；
> 它也是“先判存在再清空”，不会把已有输出截掉。

## 安全边界

* **绝不修改** `WLAN0_VAP0_*`（本机 AP，手机就是连它管的）与 `WLAN0_VAP5_*`（上游 STA）——
  改了就失联，得靠网线 + U-Boot 救。写这两组键会弹二次确认。
* `Cpe.clean()` 在退出时清掉设备端 `/tmp/.cpeout`、`/www/.cpeout`、`/tmp/.cpesh`、`/tmp/upload.img`。
* 恢复出厂 / 重启 / 升级都会断网或清配置，弹窗里写了后果。
