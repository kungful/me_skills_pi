# QQ 桌面自动化（qq-desktop-control）

Windows + QQ NT（Electron 内核）的**外部 GUI 自动化**。核心库：`qq_ctl.py`。

## 先把话说清楚：关于"不被检测到"

用户最常提的要求是"别被平台检测到，不然封号"。**没有任何方法能保证不被检测**，
但不同做法的风险差一个数量级，原因是**它们留下的痕迹根本不在同一层**：

| 做法 | 平台能看到的 | 风险 |
|---|---|---|
| **纯 GUI（本技能）** | 一次正常的鼠标点击、一次正常的按键。在 OS 输入栈里和真人**逐位相同**，没有可区分的特征 | 最低的一档 |
| 协议端（NapCat / Lagrange 等） | 非官方客户端的登录指纹、异常包序、设备信息——**特征明显** | 高，且是官方明确打击对象 |
| 注入 / Hook / 读写内存 / 驱动 | 进程被调试、模块被注入 | 最高，且是安全软件重点 |

所以"只用鼠标键盘"这个方向本身是对的，可以放心。**但它买到的是"低风险"，代价是"很脆弱"**：
布局会变、读文本困难、必须独占鼠标键盘、不能后台跑。这一点必须提前跟用户讲明白。

真正决定封不封号的是**行为**，不是工具：

- 群发广告 / 批量加好友 / 多账号矩阵 → 大概率封，什么工具都救不了
- 单账号、低频、只跟已有联系人正常来往、内容和人工发的一样 → 风险接近"人自己手滑"
- 用 `Guard` 的限流就是在守这条线，**不要为了跑得快去改它**

**本技能明确不做**（写了也不给）：进程注入、内存读写、Hook、驱动、协议逆向、
多开群控、模拟器矩阵、指纹伪装、绕过风控。这些不是"更保险的做法"，是"更快的封号方式"。

## 快速开始

```bash
cd ~/.pi/agent/skills/qq-desktop-control

python qq_ctl.py probe                 # 探测窗口/几何/限流状态
python qq_ctl.py shot                  # 截图当前 QQ 窗口
python qq_ctl.py goto "四大块"          # 搜索并进入会话
python qq_ctl.py read --target "群名"   # 进入并读最近消息
python qq_ctl.py send "内容" --target "群名"   # 演练：只输入不回车
python qq_ctl.py send "内容" --target "群名" --arm   # 真发
python qq_ctl.py stop / resume          # 急停 / 解除
```

**默认是演练模式**：不加 `--arm` 绝不会有任何东西被发出去。
演练会把内容打进输入框、截图存证，然后**清空草稿**（防止污染用户的下一条消息）。

## 定位原理（改代码前必读）

不按像素死记坐标——QQ 窗口尺寸会变（实测同一次会话里窗口从 1070×720 变成 1605×1080，
原因是被拖到另一块屏并调整）。做法是按**窗口比例**定位，见 `QQ.REL`：

| 键 | 含义 | 实测注意 |
|---|---|---|
| `search` | 左上搜索框 | 主力入口。点它 + 输入 + 点结果行，比逐行点会话列表稳 |
| `chat` | 聊天内容区 | 读消息用 |
| `input` | 输入框 | 发送用 |
| `send_btn` | 发送按钮 | 一般用回车代替 |

实测结论：QQ NT 布局是**等比缩放**的，比例坐标误差约 10px，可用；
但**输入框很大、发送按钮在右下角**，用回车发比点按钮稳。

### 键盘通道优先

能不用坐标就不用。中文输入走**剪贴板 + Ctrl+V**（实测可靠，与 IME 状态无关），
纯 ASCII 走 `SendInput + KEYEVENTF_UNICODE`（不污染剪贴板）。
`move_to()` 用二次贝塞尔曲线，避免瞬移导致 UI 还没 hover 就被点。

## 抢焦点（Windows 的硬限制）

`SetForegroundWindow` 会被前台锁定拒绝，实测直接调用报
`(0, 'SetForegroundWindow', 'No error message is available')`。
`force_foreground()` 用 `AttachThreadInput` 解除，实测可稳定拿到焦点。

## 安全阀

| 机制 | 位置 | 说明 |
|---|---|---|
| 演练模式 | `--arm` | 默认不发，只截图存证 |
| 频率限流 | `Guard` | 默认最短间隔 3s / 每小时 20 条 / 每日 120 条，超限直接抛错 |
| 急停 | `qq_ctl.py stop` | 放一个 `STOP` 文件，所有操作立即失败 |
| Esc 中止 | `Guard.check_stop()` | 操作期间按 Esc 立即停 |
| 全量日志 | `logs/YYYY-MM-DD.jsonl` | 每条动作落盘，出问题能复盘 |

**不要为了让脚本"跑快点"去调大 `Guard` 的阈值。** 那是唯一在替用户挡封号的东西。

## 实测状态（2026-11-01，Windows + QQ NT）

| 能力 | 状态 | 说明 |
|---|---|---|
| 找窗口 / 抢焦点 | ✅ | `find_qq_windows` 按 `Chrome_WidgetWin_1` + `qq.exe` 过滤，排除 Chrome |
| 点搜索框 + 中文输入 | ✅ | 截图验证："我的手机" 正确进入搜索框 |
| 搜索结果定位 | ✅ | 结果面板：工具 / 聊天记录 / 全网搜索 三段式 |
| 点击进入会话 | ⚠️ | 点 `(0.17, 0.163)` 时若搜索结果**已关闭**，会点到普通会话列表第一行 |
| 会话标题校验 | ❌ | `read_header()` 是空实现。QQ NT 单窗口模式标题恒为 `QQ`，拿不到会话名 |
| 读聊天内容 | ❌ | `Ctrl+A` 能选中全部气泡（截图已验证），但 `Ctrl+C` 回读只有碎片（实测 4 字符），**不可用** |
| 输入 + 回车发送 | ⚠️ | 通道本身可用；但**焦点没确认时会误发到当前会话**——必须在发前校验目标 |
| OCR 读屏 | 🚧 | `winsdk` 已装，`OcrEngine.try_create_from_language("zh-Hans-CN")` 路径待验证 |

**别把这些 ⚠️/❌ 当已解决。** 尤其"读消息"这条：它是"读群消息"需求的核心，
目前**没有可靠的纯 GUI 实现**。下一步优先级：

1. `winsdk` Windows OCR 读聊天区截图（零副作用：不动鼠标键盘，不选中任何东西）
2. 或用 UI Automation：QQ NT 是 Chromium，UIA 树默认是空的（懒加载），
   需 `SPI_SETSCREENREADER=1` 或收到 `WM_GETOBJECT` 后才生成 —— **实测对已运行的 QQ 无效，要重启 QQ 才生效**，代价大，暂不采用
3. 会话标题校验：可裁剪标题区域（`0.30–0.45` x, `0.02–0.07` y）做 OCR 比对

> 当前 `goto()` 的 `verify=True` 会因 `read_header()` 返回 `None` 而失败。
> **这是有意的**：宁可拒绝发送，也不在没有校验的情况下把消息发错会话。要绕过就显式传 `verify=False`。

## 踩过的坑

**1. 搜索框里按回车不是"进入第一项"。** 实测按回车后搜索结果面板关闭、右侧会话没变。
改用"点结果行"。但结果面板可能已经被上一动作关掉，那时坐标会落到普通会话列表上——**点是之前先确认面板还在**。

**2. 输入框会留残留草稿。** 实测第一次截图时输入框里已有 `我正常桌面点击c`。
发送前必须 `Ctrl+A` + `Del` 清空，否则会和新内容串在一起发出去。

**3. 不要在真实朋友的会话上做实验。** 实测过程中目标会话里的对方**正在实时回消息**
（08:14 收到"可以的"），自动化动作和真人操作混在一起，状态极难推断。
调试请一律用「我的手机 / 我的电脑」，或先建一个只有自己的群。

**4. 双屏 + 负坐标。** 本机虚拟桌面是 `-1920..1920`，QQ 可能在负坐标那块屏上。
`ImageGrab.grab(all_screens=True)` 与 `SetCursorPos` 用的是同一套虚拟桌面坐标，
保持一致就没问题；但**别假设坐标从 0 开始**。

**5. 多开。** 机器上有 5 个 `QQ.exe` 进程（多实例/辅助进程）。用面积最大的主窗口，
并靠进程名过滤掉 Chrome（同样用 `Chrome_WidgetWin_1`）。

## 换方案之前先看这张表

| 需求 | 建议 |
|---|---|
| 群管理/自动回复/定时推送，要长期稳定 | **官方 QQ 开放平台机器人**。合规、不封号；代价是要机器人权限/管理员/审核。用户嫌"不好使"通常是权限和群类型限制，先确认能不能申请 |
| 必须在自己号上、官方不可用、能接受风险 | 协议端方案。**风险显著高于本技能**，登录指纹是硬伤 |
| 就是要"看起来像人在点"、低频、人工监督下 | 本技能。慢、脆弱，但留下的痕迹最少 |
| 只想读群消息不发言 | 优先 OCR 读屏（纯像素，零副作用），比模拟键鼠更干净 |
