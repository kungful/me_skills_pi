# 开源项目封装变现 · 多平台分发（open-source-reseller）

一句话：**代码是免费的，能跑起来的环境不是。** 你卖的是「省下来的两天 + 踩过的坑 + 中文 + 出问题有人接」。

这份 skill 负责前半段（选品/审计/封装/素材），发布环节复用已有能力：

| 渠道 | 发布路径 | 能不能自动 |
|---|---|---|
| 抖音 | `douyin-ops` MCP（先 preflight + dryRun） | ✅ 能（有登录态） |
| 小红书 | `xiaohongshu` MCP（127.0.0.1:18060，有头模式） | ✅ 能（见 `xhs-courseware-post`） |
| QQ 群/频道 | `qq-order-broker` + `qq-desktop-control`（Guard 限流） | ✅ 半自动（发送需 `--arm`） |
| 闲鱼 | 人工上架 | ❌ 不做自动（阿里风控对虚拟商品极敏感） |
| B 站 | 人工投稿 | ❌ 不做自动（wbi 签名+风控，不稳定） |
| X / Twitter | 人工发，只用来选题 | ❌ 不做批量 DM |

## 0. 先把"防封"这件事说清楚（这一节比后面所有工具都重要）

你要的是"别封号"。**能买到的东西只有一个：让行为本身不像机器。**
"绕过检测"这条路（指纹伪装、多开矩阵、协议端、养号脚本）不是更保险，是更快封号——
平台判定靠的是**行为序列 + 账号关联图**，这两样都不在客户端里，改不了。所以：

```
官方 API ≻ 官方浏览器登录态 ≻ GUI 模拟（人节奏）≻ 协议端（必封）≻ 群控/指纹伪装（必封+封一片）
```

**三条铁律**：

1. **一个平台一个真人账号**，用自己用了半年以上的老号。新号 + 卖货 = 高危组合。
2. **节奏比内容重要**：每天几条写死（见 `channels.json`），不追爆量。稳定更新比冲一波安全。
3. **内容差异化**：同一素材换角度重写，绝不复制粘贴到多平台/多号。查重和同质化降权等于自己举报自己。

**明确不做（写进 `channels.json.forbidden_practices`）**：指纹伪装、协议端登录、多开群控、
批量注册养号、刷量刷评互赞、同内容多号铺、把免费开源说成自研、卖破解版、
承诺"包过/永久/无限修改"。这些不是"更激进的做法"，是"更快的死法"，而且多是违法或违约。

## 1. 生意模型：谁会为"免费的东西"付钱

| 客户 | 他的真实痛点 | 你卖什么 | 价格带 |
|---|---|---|---|
| 不懂技术的小老板 | 想用但装不上、看不懂英文 | 一键部署 + 中文文档 + 跑通 | 199–599 |
| 半懂的技术人 | 能装，但没时间踩坑 | 部署脚本 + 报错手册 | 29–99 |
| 有小团队的公司 | 要私有化/内网/定制 | 定制封装 + 汉化 + 售后 | 599–3000 |
| 长尾用户 | 只是想看看 | 教程视频/文档 | 9–49 引流 |

**定价锚点是客户的替代成本**（请人做要几天多少钱），不是你的工时。降价只会把自己变成廉价劳动力。

## 2. 选品：什么项目值得封装

`python sourcing.py search --q "topic:self-hosted" --min-stars 800 -v` 会给 0–100 分，排序逻辑：

| 维度 | 加分 | 说明 |
|---|---|---|
| License 宽松 | +25 | MIT/Apache 能直接卖成品 |
| 30 天内活跃 | +20 | 上游活着，你才不用替它擦屁股 |
| star 量级 | +0~20 | 对数计分，800 星就够用，不必追爆款 |
| 成品形态（平台/面板/工具） | +8 | 有界面 = 能截图当首图、能录演示 |
| 技术栈好封装 | +6 | Python/TS/Go，容器化容易 |
| 已归档 / 两年没动 | −40 / −15 | 卖出去就是给自己埋雷 |
| 无 License / AGPL | −30 / −10 | 见下一节，这两类是生死线 |
| issue 积压 >2000 | −6 | 售后成本会超预期 |

**"有把握"的四个具体条件**（缺一条就别上架）：

1. 你自己在干净环境里从零部署成功过 ≥1 次（含踩坑记录）
2. 能在 1 天内做出"三条命令跑起来"的交付物
3. License 允许你这么卖
4. 售后边界能写清楚（哪些不修）

## 3. License：这是生死线，不是形式主义

`python sourcing.py audit owner/repo` 会给出结论，规则如下：

| 许可证 | 能卖成品？ | 能卖托管？ | 你必须做的 |
|---|---|---|---|
| MIT / BSD / ISC / Unlicense | ✅ | ✅ | 保留版权声明与 LICENSE 原文 |
| Apache-2.0 | ✅ | ✅ | 同上 + 声明你改了哪些文件 |
| MPL-2.0 / LGPL / EPL | ✅ | ✅ | **你改过的那几个文件**要开源 |
| GPL-2/3 | ✅（分发时开源） | 通常 ✅（不算分发） | 提供完整对应源码；改了要标出来 |
| AGPL / SSPL / BUSL / Elastic | ❌ 不建议 | ❌ | 只能卖**代部署/培训/技术支持** |
| **没有 LICENSE 文件** | ❌ | ❌ | 默认保留所有权利。要么找作者要授权，要么自己重写（不抄代码） |
| 带附加条款（如 dify：多租户/去 logo 需商业授权） | ⚠ 先拿授权 | ⚠ | 内部自用通常可，对外服务前发邮件问作者 |

三个必做动作：

1. **读原文，不要只信 GitHub 那个 SPDX 标签。** 改过的 Apache（dify、部分国产项目）在 GitHub 上显示 `NOASSERTION`，实际写了"多租户服务需商业授权""不得去除 LOGO"。`audit` 会把命中的限制条款连原句一起打出来。
2. **商标不能碰。** 商品名不能叫「Dify 部署版」，要叫「基于 Dify 的 XX 部署服务」，并在商品页写明"本项目版权归原作者所有，本商品为部署/汉化/文档/售后等增值服务"。这句话同时也是**你最好的免责声明和信任背书**。
3. **拿不准就发邮件问作者。** 一封邮件比一次投诉/一次下架便宜一百倍；不少作者会直接回"只要不卖 SaaS 随便"。

## 4. 封装：从 repo 到能收钱的商品

```
python sourcing.py pack owner/repo --name "商品名（不要用上游商标）"
```

生成 `listings/<slug>/`：

| 文件 | 你要做的事 |
|---|---|
| `README.md` | 改到像人写的商品页：谁适合、拿到什么、环境要求、价格档、FAQ、售后边界 |
| `deploy/docker-compose.yml` | **模板，必须按项目真实端口/卷/环境变量改到能跑** |
| `deploy/install.sh` | 三条命令能起来；失败要能照文档手动做 |
| `deploy/.env.example` | 把必填项列全（这是新手 90% 的卡点） |
| `docs/quickstart.md` | 安装/首次配置/常见报错表/备份/升级——**报错表就是你的护城河** |

封装的质量标准（自己验）：

- 找一台**干净**的机器/容器，照 `quickstart.md` 从零走一遍，不跳步、不靠记忆
- 把每一步的真实报错记下来，写进报错表（这正是客户的痛点）
- 录一段 3–5 分钟安装演示（抖音/B站素材来源，也是售后减负工具）
- 验收点写死：能打开界面 + 核心功能跑一次 + 重启后仍可用

## 5. 分发素材：一个项目，六套话术

```
python sourcing.py kit <slug>
```

`kit/` 下六个文件：`xiaohongshu.md` `douyin.md` `bilibili.md` `xianyu.md` `qq_group.md` `twitter.md`。
**它们是草稿，不是成品**——直接发出去就是同质化内容，会被降权。改的时候守住各渠道的雷：

| 渠道 | 内容形态 | 每天上限 | 立刻违规的雷 |
|---|---|---|---|
| 小红书 | 图文 3:4 封面 + 6–9 图，标题 ≤20 字 | 1–2 篇 | 正文/图里出现微信、QQ、vx、站外链接 |
| 抖音 | 竖屏 15–45s，前 3 秒出结果画面 | 1–3 条 | 口播念联系方式、搬运他人视频、同视频多号发 |
| 闲鱼 | 标题 ≤30 字塞满搜索词，首图=成品截图 | 3–5 条 | 详情写微信/QQ、多号铺同款、"包过/永久"、卖破解版 |
| B 站 | 5–15 分钟教程，标题写清"开源+工具名+能干什么" | 1–2 条 | 商业内容不标注、标题党、录屏当原创 |
| QQ 群 | 先潜水 2–3 天，真需求走私聊 | 1–2 条/群 | 群发广告、批量加好友、拉人进群就推销 |
| X | 英文一句话 + 动图；回复痛点推文 | DM ≤5 | 新号大量关注/取关、批量 DM 带链接 |

**导流话术的正确写法**：不写"加我微信"，写"评论区留言『部署』，我一条条回"。
既安全，又能筛出真实需求（愿意留言的人才会付钱）。

## 6. 成交与售后（决定你是做一单还是做一年）

- **先聊 2–3 轮再报价**：问清环境（服务器/本机、系统、内存）、用途（自用/团队/给客户）、要什么交付。秒回模板话术在闲鱼=机器号。
- **定金**：自助包全款；代部署 50%；定制 30% 起、拆里程碑。
- **写清不包含什么**：服务器费用、第三方 API 费用、上游大版本变更导致的适配、你机器上的历史环境污染。
- **含 1 次修改**，超出另报价。这句话能挡掉 80% 的返工。
- **纠纷处理**：虚拟商品优先退款换好评。一条差评的长期成本远高于一单利润。
- **收款后立刻做三件事**：归档交付物、录一段"客户验收通过"的截图（素材）、问一句"还有哪里想改"（复购入口）。

---

## 7. 复购与规模化（比多平台铺货更重要）

1. **一个项目做四个档位**（自助包/代部署/定制/托管），同一份工作卖四次。
2. **做成系列**：B 站合集、小红书"自部署工具"专题、群里"每周一个能跑的工具"。系列比单条吃长尾。
3. **把客户沉淀成群**：买了自助包的人拉一个小群，下一个项目的首批客户就在里面。
4. **一个渠道做深再开下一个**。同时铺五个平台、每个都半成品，是最常见的失败方式。

## 10. 坑

1. **GitHub 上 `NOASSERTION` 不等于宽松。** 国产/大厂项目喜欢"Apache + 附加条款"，`audit` 的限制条款扫描就是为这个写的——不要跳过它。
2. **官方镜像 ≠ 一定能跑。** 很多项目 compose 里写了 `build: .` 却缺构建上下文；交付前必须干净环境跑一遍。
3. **"一键部署"这个词会被举报。** 如果你的脚本只覆盖了 Ubuntu 22.04，就写清"Ubuntu 22.04 验证，其它系统需手动"，别写"支持所有系统"。
4. **闲鱼虚拟商品最怕"秒回 + 模板"。** 第一条回复必须问环境/用途，且慢 1–3 分钟再发。
5. **抖音搬运判重不看片头看画面。** 别人的演示录屏哪怕改片头也会被判搬运；自己录，画面里带上自己的界面/终端。
6. **小红书导流是硬红线**，但"评论区留言"是安全的：把成交动作放到私信里，别放在正文里。
7. **别一次开五个平台。** 一个渠道跑通转化（有人问价、有人下单）再复制，否则五个都半死。

## 11. 这套什么时候不该用

| 你想要的 | 结果 | 该做什么 |
|---|---|---|
| 把免费开源说成自研卖高价 | 虚假宣传 + 侵权，商品页就有举报入口 | 明说"基于 XX 封装"，把工时讲成价值 |
| 卖破解版 / 去授权 / 共享账号 | 侵权，闲鱼号会被牵连 | 不做，这不在技术难度范畴 |
| 一次铺 50 个商品、多个号 | 同质化 + 关联判定，一锅端 | 一个项目做深，做系列 |
| 靠脚本自动养号涨粉 | 行为模型早已覆盖，白花钱 | 内容差异化 + 稳定节奏 |

**判断标准很简单**：如果这件事被客户和平台同时知道真相后你还敢做，就做；不敢，就是这条线。
