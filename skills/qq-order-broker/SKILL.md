# QQ 找单 · 接单 · 交付（qq-order-broker）

一条完整流水线：**读屏找单 → 能力判定 → 私聊对接 → 报价收定金 → 自己动手交付 → 归档复盘**。

它建在 `../qq-desktop-control` 之上，分工是刻意的：

| 层 | 谁做 | 关键约束 |
|---|---|---|
| 碰 OS 的那层（鼠标键盘、截图、限流） | `qq_ctl.py` | 唯一会留痕迹的地方，只有一处实现 |
| 业务层（找单/判定/话术/订单库/交付） | 本技能的 `orderbot.py` | 不发消息、不点按钮，只读屏 + 落盘 |

**先读这条：**你在群里扮演的是「一个手上有真本事的接单人」，不是「一台报价机器」。
群规、账号安全、交付口碑，任何一条坏了都比少接一单亏得多。

## 1. 能力边界（这一节决定接不接，必须一眼看完）

真话先讲：**能接的活，是「本机 Pi 现在就能做出可验证成品」的活**。做不到的别接，
接了交不出来比不接惨十倍。

### A. 能接（可以直接报价）

| 类别 | 典型活 | 参考价 | 交付物 |
|---|---|---|---|
| 脚本 / 自动化 | 批量改名、定时抓取、自动点按、RPA、一键工具 | 100–600 | 脚本 + README + 跑通截图 |
| 数据处理 / Excel | 汇总、清洗、对账、透视、公式地狱 | 80–400 | 成品表 + 可复用脚本 |
| 爬虫 / 采集（公开数据） | 商品/行情/公开页面导出 | 200–1200 | 采集脚本 + 样例数据 |
| 网页 / 前端 | 落地页、改样式、静态站、后台管理 | 300–2000 | 源码 + 部署说明 |
| 后端 / 接口 | 小 API、登录注册、数据库设计 | 500–3000 | 可跑服务 + 接口文档 |
| 部署 / 运维救急 | nginx、docker、SSL、迁移、上线 | 100–600 | 可用环境 + 回滚说明 |
| 排错 / 救急 | 报错、502、启动失败、依赖地狱 | 80–500 | 根因说明 + 修好 |
| AI 接入 | 大模型 API、知识库、提示词、客服 bot | 300–2500 | 可跑代码 + 成本估算 |
| 出图 / 设计图 | 海报、封面、logo、效果图 | 50–300 | 成品图（按尺寸） |
| 课件 / 详情页 | PPT、教案、长图详情、主图 | 100–800 | PPTX/PDF/长图 |
| 视频 / 字幕 / 配音 | 剪辑、字幕、配音、转码 | 100–600 | mp4 + srt |
| 文档 / 文案 / 翻译 | 简历、方案、报告、润色 | 50–400 | docx/md |
| 3D / CAD | 建模、外壳、stl/step | 200–1500 | 模型 + 尺寸图 |
| 硬件 / PCB | 原理图审查、改板、Gerber、BOM | 300–2500 | 源文件 + 风险说明 |
| 安卓 / APK | 打包、签名、装机、简单改动 | 200–1200 | apk + 装机说明 |
| 数据分析 / 报表 | 看板、分析报告、可视化 | 200–1000 | 结论 + 图表 |
| 逆向（**有授权**） | 分析自己的/客户有处置权的程序 | 500–3000 | 报告 + 调用链 |
| 作业辅导 | 只讲思路，不代写不代交 | 50–300 | 讲解 + 可复述版本 |

价格表在 `caps.json`（机器读的那份），**这张表和人看的一致，改一处就要改另一处**。

### B. 要先确认，不能直接接（`half`）

- 涉及真实资金 / 代操盘 / 跑分 → 只做工具演示，**绝不代人操作账户**
- 要登录客户或第三方账号 / 要验证码 → 现在、以后都不接
- 长期维护 / 驻场 / 包月盯 → 超出单次交付，走人工谈
- 对公、发票、盖章、走公账 → 主体资质问题，人工处理
- 需求模糊到"你看着办" → 先问诊，验收标准定不下来就不接
- 工期不现实（半小时要做完一周的活）→ 加价或拒，别硬扛

### C. 永不接（`banned`，命中就只发拒绝模板）

代写论文/代考/代做毕设 · 破解入侵免杀木马钓鱼 · 外挂多开批量注册 ·
刷单刷量水军假流量 · 盗号开盒查人隐私数据 · 赌彩资金盘 ·
洗钱代收两卡 · 假证假发票 · 无授权打别人站点 · 代实名/绕过风控/解封账号

> 命中红线时**不解释、不议价、不推荐替代方案**，一句"这个不在我能接的范围"结束。
> 解释等于给他砍价和说服你的入口。

## 2. 流水线（状态机）

```
candidate ──ask──> contacted ──qualify──> qualified ──quote──> quoted
   │                                                        │
   └──decline──> dead                              accept ───┘
                                                     ↓
                                      accepted → delivering → delivered → paid → close
```

状态存在 `orders/<id>.json`，`send` 会自动推进，也可以 `status` 手动改。
**不允许跳步**（`draft` 会拦：没报价就直接 accept 的，`--force` 才能绕）——跳步是纠纷的源头。

## 3. 命令速查

```bash
cd ~/.pi/agent/skills/qq-order-broker

# ① 找单：进群 → 截图 → OCR → 打分 → 入队（只读，不点不输入）
python orderbot.py triage --target "接单群A,接单群B"

# ② 看判定：能力匹配 / 红线 / 建议报价 / 必问项
python orderbot.py verdict <id>

# ③ 对接：先拿草稿（不发送）
python orderbot.py draft <id> --stage ask
python orderbot.py send  <id> --stage ask --to 客户昵称 --arm     # 真发

# ④ 读客户回复（只读，替代不可靠的 Ctrl+A/Ctrl+C）
python orderbot.py read --target "客户昵称"

# ⑤ 状态与报价
python orderbot.py status <id> qualified --contact "客户昵称" --quoted 300
python orderbot.py list --status candidate,quoted
python orderbot.py show <id>          # 全量 JSON（含历史）

# ⑥ 交付
python orderbot.py deliver <id> --files "dist/*" "README.md"

# ⑦ 安全阀
python orderbot.py stop     # 放 STOP 文件，所有发送立即失败
python orderbot.py resume
python orderbot.py stats    # 订单统计 + 今日发送配额

# ⑧ 定时盯（只读轮询，不发消息）
python orderbot.py watch --target "接单群A" --interval 900 --rounds 8
```

离线自测（不碰 QQ）：`python orderbot.py scan --img 某张QQ截图.png`、`python selftest.py`。

### 话术阶段（`--stage`）

`ask` 首次接触 · `qualify` 问诊六问 · `quote` 报价 · `accept` 确认开工（复述验收标准）·
`progress` 进度同步 · `deliver` 交付 · `chase` 催尾款 · `decline` 拒单 ·
`decline_banned` 红线拒绝 · `close` 收尾

模板在 `templates.json`，槽位 {$价格/工期/交付物} 由 `verdict` 的计算结果自动填。

## 4. 找单是怎么实现的（读屏，不是读协议）

```
截图（PIL ImageGrab，含负坐标多屏）
  → Windows OCR（winsdk / Windows.Media.Ocr，语言包 zh-Hans-CN）
  → 行聚合成"气泡块"（垂直间距阈值 0.020×H）
  → 丢噪声（时间戳 / 纯数字 / 1-2 字 / UI 词）
  → 丢侧栏（用「会话标题的 x」自动推断聊天面板左边界，见 detect_chat_left）
  → 打分（caps.json）+ 去重（指纹 = 归一化文本 sha1 前 16 位，存 orders/seen.json）
  → orders/<id>.json
```

**为什么不沿用 `Ctrl+A` + `Ctrl+C`：**上游实测那条路只能回读到 4 个字符的碎片，还会污染
剪贴板。OCR 是纯像素读取，零副作用、不动键鼠、不选中任何东西——读群消息就该走这条。

**打分公式**（`score_text`）：能力标签命中数 × 权重 + 意图词（求/有偿/预算/报酬…）加分 2；
红线命中直接 `decline`；≥5 且带意图 → `take`；≥2 → `careful`；否则 `skip`（不入队）。
客户自己报了价（"预算 300"）时，建议价按 `[0.95×报价, 1.5×报价]` 贴着走，不自作聪明抬价。

**标题校验（发消息前必过）：**`goto` 之后截图 OCR 顶部标题区（x>0.24W 排除搜索框，
y<0.10H），与目标名做归一化包含 + `difflib` 相似度 ≥0.7 才算进对会话，**否则直接抛错不发**。
上游 `read_header()` 是空实现，这层校验是本技能补的——宁可失败，绝不发错人。

## 5. 对接聊：三条铁律

1. **不群发、不 @ 全体、不在群里刷回复。** 找到需求就到私聊去谈（`--to 昵称`）。
   群里刷话术是最快被踢+被举报的路，也是账号风险最高的一种行为。
2. **先问诊，再报价。** 报价前必须拿到：要什么 / 素材在哪 / 什么时候要 / 预算 / 验收标准 / 交付格式。
   每轮最多问 6 个问题，两轮问不清就放弃——问不清的需求做出来必然不满意。
3. **一句一句像人话。** 不写"亲，您好，我们提供一站式解决方案"。写："这块我能做，先确认两点……"

### 报价与收款

- 贴客户预算报，别用自己的下限去顶人家的上限；低于 80 的活直接不接（沟通成本大于收入）。
- **先定金后开工**：50%（不足 100 的可以全款，金额再大就拆里程碑）。
- 明确写"需求中途新增另算"——这句话能省掉 80% 的返工纠纷。
- 交付后必走验收：验收点写死了才付尾款。不做"做完你自己看吧"。
- 尾款只催一次（`chase` 模板），第二次就归档为坏账，别耗时间在烂账上。

### 骗子识别（`caps.json.red_flags`，命中任一条就停）

先干活后付钱（>300）· 让你交保证金/押金 · 只发"在吗"不肯说需求 ·
一边加需求一边不提钱 · 先要完整成果再"看效果决定要不要"（等于白拿）·
自称公司却要你垫钱 · 十分钟内要报价和开工 · 拿别人源码让你"改成我们的" ·
让你签保密协议却不给材料。

## 6. 为什么默认半自动（不是不会做全自动）

`send` 不加 `--arm` **一定不会发出任何东西**，`triage` 只把第一句话写进
`orders/<id>/ask.txt`。这是刻意的：

- 首触话术发错群 / 发错人 = 社交性死亡 + 被举报
- 单价、工期、验收判断需要一次人的确认，机器拍板的报价迟早出事
- 一条 `--arm` 的成本是 2 秒；发错一次的修复成本是半小时加一个差评

**全自动可以开的口子**：已经 `accepted` 的单，跟进/进度/催款这类"熟客追问"，
可以在 `send` 外面套你自己的循环脚本（Guard 仍然限流 3s / 20 每小时 / 120 每天，
`orderbot.py stop` 随时急停）。**首触与报价不要自动化。**

## 7. 交付：交付物的质量就是你的复购率

`deliver` 会建 `orders/<id>/deliver/` 和 `handoff.md`，Handoff 必须写全四段：

1. 怎么装、怎么跑（依赖版本写死）
2. 验收点清单（对着客户原话逐条勾选）
3. **已知限制**（提前说，别等客户发现）
4. 售后范围（一次免费修改，超出另报价）

交付前自己跑一遍；跑不通就不发。交付即存档：截图 + 源文件 + 聊天记录都在
`orders/<id>/` 里，出纠纷能翻出来。

## 8. 实测状态（2026-11-01，Windows 11 + QQ NT）

| 能力 | 状态 | 证据 |
|---|---|---|
| Windows 中文 OCR 读屏 | ✅ | `zh-Hans-CN` 语言包可用，汉字+坐标都拿得到 |
| 聊天区/侧栏自动切分 | ✅ | 主窗口标题 x=499/1507 → 自动得左边界 0.32，侧栏整列被滤掉 |
| 气泡分块 | ✅ | 同一截图 33 行 → 3 块（块内行距 +9/+12，块间 +46/+80） |
| 需求打分 / 红线拦截 | ✅ | `selftest.py`：代写论文/外挂/解封 → decline，跑腿闲聊 → skip |
| 进会话 + OCR 标题校验 | ✅ | 目标"四大地区" OCR 得"四大地"（丢字），相似度 0.86 → 通过 |
| 读客户回复（`read`） | ✅ | 读屏输出气泡文本，不碰剪贴板 |
| 发消息 | ⚠️ 通道可用，未做真实投递 | 受 `--arm` 保护；首次真发请先对「我的手机 / 自建测试群」跑一遍 |
| 扫描到真实需求 | ⚠️ 取决于群内容 | 群必须开着且有新消息；实测样本群当时只有空聊天，抽出 0 条 |
| QQ 频道 | ⚠️ 未单独验证 | 频道在 QQ NT 里同样是窗口文本，`--target 频道名` 走同一路径；建议先用 `--img` 对频道截图试 |

**已知限制（写出来比藏着好）：**

- 截图必须 QQ 在前台（会抢焦点）；不能后台静默跑。
- 长消息被折叠时 OCR 只能读到可见部分 → 长需求要 `read` 后手动往上滚再读一次。
- 图片/表情包里的文字读不到（除非那张图本身就清晰且是文字图）。
- 富文本表格在 OCR 里会变成一行行文字，结构信息会丢。

## 9. 坑

1. **QQ 布局会变、窗口会缩放。** 所有坐标是比例 + 运行时探测，别写死像素；
   换主题/换版本后先 `python orderbot.py layout --img 截图.png` 重新校准。
2. **群名要写全。** 标题 OCR 会丢字（"四大地区"→"四大地"），所以校验用相似度；
   但群名本身只剩两三个字时容易误判，那种情况先手动点进会话。
3. **别在别人的私聊里试验。** 调试一律用「我的手机 / 我的电脑 / 自建空群」。
4. **别为了提高检出率把 `skip` 阈值调低。** `skip` 拦掉的正是"在吗""好的""哈哈"这种噪声，
   放宽后订单库里 90% 是垃圾，`triage` 就不再有用了。
5. **`seen.json` 是去重的地基。** 删了它会重复入队；但也别怕删——验证流水线时清空是正常操作。
6. **不要在同一个群里反复 `scan`。** 每次都要抢前台；现实节奏是 15–30 分钟一轮，
   人不在就让 `watch` 跑，别 30 秒一轮把机器占死。

## 11. 什么时候说明这套不合适

| 情况 | 该换什么 |
|---|---|
| 想长期稳定做客服/自动回复，怕封号 | 官方 QQ 开放平台机器人（合规，但要权限审核） |
| 只想刷屏发广告拉客户 | **别做**。任何工具都会封号，且这里不提供 |
| 想在几十个群里自动铺话术 | 不做。这是群控/群发，属于本技能明确排除的范围 |
| 需求本身不在能力内 | 不接。转人工或直接拒绝，这是专业度的一部分 |
